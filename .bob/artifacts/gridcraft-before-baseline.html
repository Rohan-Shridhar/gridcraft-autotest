1. Project Overview

GridCraft is a browser-based pixel-art tool built with React 19 + Vite. Users paint on resizable grids (16×16 to 128×128), use flood-fill, erase, undo/redo, export to PNG, and import images. It is deployed to Vercel at gridcraft-by-me.vercel.app.

2. Architecture

All application state lives in a single root component. There is no Context API, no external store, and no routing library.

FileRoleKey state / concern
App.jsxRoot — owns all statecells[], history[], future[], gridSize, tools, theme, import/export logic
Grid.jsxRenders pixel gridMouse events, coordinate labels, paint-on-drag
Tools.jsxToolbar (undo/redo, eraser, fill, brush, color, clear)Passes actions back to App via props
Menu.jsxTop menu (export, import, shortcuts modal, links)Monkey-patches HTMLAnchorElement.prototype.click during export
Header.jsxTitle + theme toggleReads isDarkTheme prop
Contributors.jsxGitHub contributors marqueeLive GitHub API fetch on every mount
ErrorPage.jsx404 fallbackRendered by path check — unreachable in production
toastMessages.jsMutationObserver — strips leading emoji from toastsSide-effect-only import; no exports
main.jsxReact entry pointInjects Vercel analytics

State Model

Grid = flat 1-D array of length gridSize². Each element is null (transparent) or a hex colour string. Index math: row = Math.floor(idx / gridSize), col = idx % gridSize. Every paintCell call pushes a history snapshot; cap = 15 entries.

3. Confirmed Bugs

BUG-1 Theme toggle is inverted (AGENTS.md known bug)

App.jsx:48 — document.body.classList.toggle('light-theme', prev) uses prev (the old value) as the force flag instead of !prev. The body class is toggled to match the previous state, meaning light-theme is added when switching to dark and removed when switching to light. Theme is always one click behind.

BUG-2 isSmallScreen state is computed but never used

App.jsx:41 — isSmallScreen is initialised with a bare window.innerWidth read (breaks SSR / jsdom), kept in sync on resize, but is never referenced anywhere in the JSX or logic. Mobile users get only a toast message; no layout or capability changes are applied.

BUG-3 ErrorPage is unreachable in production

App.jsx:383–386 + vercel.json — Vercel rewrites every path to /index.html, so window.location.pathname is always "/". The 404 branch never fires on the live deployment; ErrorPage is dead code in production.

BUG-4 Favicon path is wrong

index.html:5 — href="./public/logo.png" is incorrect. Vite serves public/ at /; the correct path is /logo.png. The favicon is broken for the Vite dev server and production build.

BUG-5 exportWithFilename is defined but never called

Menu.jsx:7–30 — A full custom-filename export flow (with prompt + filename sanitisation + prototype patch) is implemented but the export button (Menu.jsx:37) calls downloadImage directly, bypassing it entirely. The feature is silently absent.

BUG-6 changeGridSize unconditionally hides grid for ≥32

App.jsx:189 — setShowGrid(newSize < 32) forces grid lines off for 32×32, 64×64, and 128×128, overriding any prior user preference without warning. A user who explicitly enabled the grid on a 64×64 canvas loses it on every grid-size change.

4. Code-Quality & Design Issues

#SeverityLocationDescription
CQ-1 WARN App.jsx:209 floodFill captures gridSize from the outer App closure. Extracting it to a utility file (for testing) requires passing it as an explicit parameter — a refactor blocker.
CQ-2 WARN package.json:19 "type": "commonjs" is declared but the entire codebase uses ESM (import/export). Misleading; could break tooling that respects this field.
CQ-3 WARN index.html:6, 11–16 Duplicate <link rel="preconnect"> blocks for Google Fonts — identical declarations repeated twice, adding unnecessary DNS round-trips.
CQ-4 WARN index.html:26 SEO meta description still says "16x16 grid" even though the app supports up to 128×128. Stale documentation.
CQ-5 WARN Grid.jsx:91 key={index} used for grid cells. Using array index as key prevents React from efficiently reconciling reorders and is a React anti-pattern.
CQ-6 WARN src/index.css:342–354 Hard-coded background-color: white; color: black in .tool-btn--active and .tool-btn--fill-bg break light-mode theming. These should use CSS custom properties.
CQ-7 INFO App.jsx:118 / Tools.jsx:157 window.confirm() used for destructive confirmations (clear canvas, grid size change, complex import). Blocks the browser event loop; not testable; not customisable. Three separate call sites with slightly different messages.
